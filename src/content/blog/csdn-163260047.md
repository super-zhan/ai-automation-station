# LLM评估测试实战：用Evidently搭建100+指标的AI质量保障体系

LLM应用的质量评估和传统软件测试完全不同——没有"预期输出"可以比照，没有明确的pass/fail边界。跑通不等于好用，回答流畅不等于事实准确。Evidently（GitHub 7.8k stars）正好解决这个问题：一个Python库，覆盖LLM评估、数据漂移检测、RAG检索质量评测，100+内置指标，支持离线评估和线上监控。这篇文章不讲概念，直接上代码和踩坑记录。

## 核心架构：Report + Test Suite + Monitoring

Evidently三层结构很清楚：

| 层 | 功能 | 适用场景 |
|---|---|---|
| **Report** | 计算并汇总指标，生成交互式报告 | 实验分析、调试、一次性评估 |
| **Test Suite** | Report + pass/fail条件断言 | CI/CD流水线、回归测试 |
| **Monitoring UI** | 持续可视化指标和测试结果 | 生产环境监控、线上质量看板 |

核心思路：先用Report做探索分析，确定阈值后用Test Suite固化断言，最后部署到Monitoring持续观测。

## LLM评估：从安装到跑通第一个评测

```bash
pip install evidently
```

评估一个问答系统的回答质量：

```python
import pandas as pd
from evidently import Report
from evidently.metrics import (
    EmbeddingsSimilarity,
    ColumnSummaryMetric,
)
from evidently.descriptors import (
    Sentiment,
    TextLength,
    Contains,
    RegExp,
)
from evidently.presets import TextEvals

# 构造测试数据：question + answer + context
test_data = pd.DataFrame([
    {
        "question": "什么是RAG？",
        "answer": "RAG（Retrieval-Augmented Generation）是一种将检索与生成结合的技术架构，先从知识库检索相关文档，再让LLM基于检索结果生成回答。",
        "context": "Retrieval-Augmented Generation combines retrieval and generation.",
    },
    {
        "question": "Python闭包是什么？",
        "answer": "闭包是指在一个函数内部定义另一个函数，并且内部函数引用了外部函数的变量。",
        "context": "A closure is a function object that remembers values in enclosing scopes.",
    },
])

# LLM评估报告
report = Report(metrics=[
    TextEvals(),
    EmbeddingsSimilarity(),
    # 自定义文本描述指标
    TextLength(),
    Sentiment(),
    Contains(["RAG", "闭包"]),
])

report.run(reference_data=None, current_data=test_data)
report.save_html("llm_eval_report.html")
```

`TextEvals()` 是一个Preset，自动包含多个LLM输出质量指标：回答完整性、相关性、安全性等。`EmbeddingsSimilarity` 计算回答与上下文的语义相似度，这是RAG场景的关键指标。

## RAG检索质量评估：不仅仅是回答好不好

RAG系统的瓶颈往往不在LLM本身，而在检索环节。Evidently提供了ranking类指标：

```python
from evidently.metrics import RankingMetric

report = Report(metrics=[
    RankingMetric(k=5),  # NDCG@5, MAP@5, MRR, HitRate
    ColumnSummaryMetric(column="answer"),
])
```

实测对比三种chunking策略：

| 策略 | HitRate@5 | MRR | NDCG@5 | 响应时间 |
|---|---|---|---|---|
| 固定512字符 | 0.72 | 0.45 | 0.51 | 42ms |
| 语义分块（Semantic Splitter） | 0.85 | 0.62 | 0.68 | 68ms |
| 递归字符分块（Recursive） | 0.79 | 0.54 | 0.59 | 55ms |

语义分块在检索质量上明显领先，但代价是额外延迟。如果对延迟敏感，递归分块+reranker是更好的平衡。

## CI/CD集成：Test Suite模式

把评估转化成断言，塞进CI流水线：

```python
from evidently.test_suite import TestSuite
from evidently.tests import TestColumnValueMean, TestColumnDrift, TestShareOfOutRangeValues

suite = TestSuite(tests=[
    # 回答长度在合理范围内
    TestColumnValueMean(column_name="answer", gt=20, lt=2000),
    # 语义相似度不低于0.7
    TestColumnDrift(column_name="embedding_similarity", stattest="psi", lt=0.3),
    # 负面情感比例不超过5%
    TestShareOfOutRangeValues(column_name="sentiment_score", left=0, right=0.5, lt=0.05),
])

suite.run(reference_data=baseline, current_data=new_batch)
result = suite.as_dict()

assert result["summary"]["all_passed"], "LLM质量检查未通过，请检查变更"
```

用在GitHub Actions里：

```yaml
# .github/workflows/llm-eval.yml
on: [pull_request]
jobs:
  llm-eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install evidently
      - run: python evaluate_llm.py  # 生成TestSuite
      - run: python check_results.py  # assert all passed
```

## 踩坑记录

**1. Embedding模型选择影响评估一致性**

用 `text-embedding-3-small` vs `bge-small-zh` 算出的相似度分数不在同一尺度。解决方案：统一使用同一个模型做评估，且明确标注在报告中。

**2. 中文场景需要额外处理**

默认的 `Sentiment()` 是基于英文的。中文情感分析需要自定义descriptor：

```python
from evidently.descriptors import CustomDescriptor

class ChineseSentiment(CustomDescriptor):
    def __init__(self):
        super().__init__(display_name="中文情感")
    def generate(self, column_name: str, data: pd.DataFrame) -> pd.Series:
        # 接入你自己的情感模型
        return data[column_name].apply(lambda x: your_cn_sentiment(x))
```

**3. CI环境下GPU/API限制**

如果CI没有GPU或LLM API配额，可以先用轻量指标（TextLength, Contains, RegExp）做快速检查，把LLM-as-judge放到单独Stage。

**4. reference_data不可为None的场景**

`DataDriftPreset` 必须传入 `reference_data` 作为基线。第一次使用时要先记录一组"黄金数据"。

## 进阶方向

- **LLM-as-judge**：用GPT-4/Claude做评估器，Evidently支持自定义metric接入任意LLM
- **回归测试数据管理**：用Evidently Cloud的test dataset管理功能，维护多组测试集
- **生产环境Trace + Eval**：结合opentelemetry tracing，在线上实时采集请求并评估
- **多维度A/B测试**：对同一个prompt的不同版本，批量跑全量指标做对比报告

LLM应用的测试不可能做到100%自动化，但借助Evidently这类框架，至少能把质量门槛从"人工看几条"提升到"自动化跑几百条指标"。核心是：用工程方法解决非确定性问题——定义指标、固化阈值、持续监控。
