# Playwright Mock API 进阶：Route 拦截、条件模拟与请求篡改实战

UI 自动化最头疼的问题之一就是外部依赖不稳定。第三方 API 限流、环境数据不一致、支付接口无法在测试环境真实调用——这些都是拦路虎。Playwright 的 Route API 提供了浏览器级别的网络请求拦截能力，可以在请求发出前或响应返回前进行任意修改，无需 mock server、无需改代码、无需代理工具。

## Route 拦截的核心机制

Playwright 的 `page.route()` 工作在 Chromium 底层网络栈层面，比传统 Selenium 的 Proxy 模式更高效。它拦截的是 CDP（Chrome DevTools Protocol）的 `Fetch.requestPaused` 事件，理论上可以拦截任何类型的网络请求——XHR、Fetch、WebSocket、图片、字体、CSS 都行。

基本拦截模型：

```
请求 → [Playwright Route Handler] → 放行/修改/中止 → 浏览器处理
```

## 基础用法：四种拦截模式

### 1. 直接中止请求

屏蔽不需要的资源类型，大幅提升测试速度：

```python
import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    
    # 屏蔽图片和字体加载（测试通常不需要验证这些）
    page.route("**/*.{png,jpg,jpeg,gif,svg,woff,woff2}", lambda route: route.abort())
    page.route("**/*.css", lambda route: route.abort())
    
    page.goto("https://example.com")
    # 页面加载速度可提升 40%-60%
```

实测数据：在一个电商后台管理系统（40+ 组件、200+ API 请求）中，屏蔽静态资源后首屏加载时间从 6.2s 降到 2.8s。

### 2. 修改请求头/体

某些接口需要特定的认证头，或需要注入测试标识：

```python
def handle_request(route):
    headers = route.request.headers
    headers["X-Test-Mode"] = "true"
    headers["Authorization"] = "Bearer test-token-123"
    route.continue_(headers=headers)

page.route("**/api/**", handle_request)
```

注意：`route.continue_()` 只能修改 `headers`、`method`、`postData`、`url` 四个字段。要修改请求体内容，需要先拦截请求，自己重新发送。

### 3. 伪造响应数据

最常用的模式——绕过后端，返回固定数据：

```python
def mock_user_list(route):
    # 完全绕过后端请求，直接返回 mock 数据
    route.fulfill(
        status=200,
        content_type="application/json",
        body=json.dumps({
            "users": [
                {"id": 1, "name": "测试用户A", "role": "admin"},
                {"id": 2, "name": "测试用户B", "role": "editor"},
            ],
            "total": 2,
            "page": 1
        })
    )

page.route("**/api/v1/users**", mock_user_list)
```

### 4. 条件拦截：只改部分响应

有时只修改响应中的某个字段，其余保持原样——先发真实请求，再篡改响应：

```python
async def alter_response(route):
    response = await route.fetch()
    body = await response.json()
    
    # 只把余额改成特定值，其余不动
    if "balance" in body:
        body["balance"] = 999999.00
    if "subscription" in body:
        body["subscription"]["status"] = "active"
    
    route.fulfill(
        status=response.status,
        headers=response.headers,
        body=json.dumps(body)
    )

page.route("**/api/user/profile", alter_response)
```

这是 Playwright 相比传统 mock 工具（如 WireMock、MockServer）的核心优势——不需要预先定义全部响应结构，只需要关注你要改的那几个字段。

## 高级模式：动态 Mock 工厂

在实际项目中，100% 的接口都 mock 是不现实的。更实用的做法是按场景动态切换：

```python
class MockManager:
    def __init__(self, page, scenario="default"):
        self.page = page
        self.scenario = scenario
        self._routes = {}
    
    def register(self, url_pattern, scenario_data: dict):
        """注册 mock 场景数据"""
        self._routes[url_pattern] = scenario_data
        self.page.route(url_pattern, self._handler)
    
    def _handler(self, route):
        url = route.request.url
        for pattern, scenarios in self._routes.items():
            if pattern not in url:
                continue
            # 根据当前场景选择不同数据
            if self.scenario in scenarios:
                route.fulfill(**scenarios[self.scenario])
                return
            # 默认回退
            if "default" in scenarios:
                route.fulfill(**scenarios["default"])
                return
        route.continue_()
    
    def switch_scenario(self, scenario):
        """运行时切换测试场景"""
        self.scenario = scenario

# 使用示例
mock = MockManager(page, scenario="empty_state")
mock.register("api/v1/orders", {
    "default": {
        "status": 200,
        "content_type": "application/json",
        "body": json.dumps({"orders": [], "total": 0})
    },
    "has_data": {
        "status": 200,
        "content_type": "application/json",
        "body": json.dumps({"orders": [...], "total": 100})
    },
    "error": {
        "status": 500,
        "content_type": "application/json",
        "body": json.dumps({"error": "Internal Server Error"})
    }
})

# 测试空状态 UI
page.goto("/orders")
# 切换到有数据场景
mock.switch_scenario("has_data")
page.reload()
```

## 踩坑记录

### 1. Route handler 超时

Playwright 默认每个 route handler 有 30 秒超时。如果你的 mock 逻辑需要调用外部服务（比如从文件读取数据），可能会超时：

```python
# 方案一：增加超时
page.route("**/api/**", handler, timeout=60000)

# 方案二：异步 handler 中用 route.fetch() 
# fetch 默认也带超时，需要全局配置
page.set_default_timeout(60000)
```

### 2. `page.route()` 和 `page.route_from_har()` 的冲突

如果同时设置了全局 route 和 HAR 回放 route，后设置的路由优先级更高但不是完全覆盖。建议在 fixture 级别统一管理：

```python
@pytest.fixture
def mock_api(page):
    routes = []
    def _add_route(pattern, handler):
        routes.append(pattern)
        page.route(pattern, handler)
    yield _add_route
    for pattern in routes:
        page.unroute(pattern)
```

### 3. JavaScript 发起的请求和页面导航请求

`page.route()` 默认拦截所有请求，但 navigation 请求（`page.goto()` 的主文档请求）也会被拦截。如果拦截了主文档请求并调用 `route.abort()`，页面会白屏。使用 glob pattern 精确定位 API 路径：

```python
# 只拦截 API 请求，不碰文档和资源
page.route("**/*/api/**", handler)  # 路径中带 /api/ 才拦截
# 或者明确限定域名
page.route("https://api.example.com/**", handler)
```

## 与 Playwright Test 集成

在 `@pytest.mark.parametrize` 中使用 mock 场景做数据驱动测试：

```python
import pytest

test_data = [
    ("empty", {"orders": [], "total": 0}, "订单空状态展示正常"),
    ("normal", {"orders": SAMPLE_ORDERS, "total": 50}, "订单列表完整展示"),
    ("paginated", {"orders": PAGE_ORDERS, "total": 150}, "分页器正常显示"),
    ("error", None, "错误状态有提示信息"),
]

@pytest.mark.parametrize("scenario,mock_data,desc", test_data)
def test_order_list_scenarios(page, scenario, mock_data, desc):
    if mock_data:
        page.route("**/api/v1/orders**", lambda route: route.fulfill(
            status=200,
            body=json.dumps(mock_data)
        ))
    else:
        page.route("**/api/v1/orders**", lambda route: route.fulfill(
            status=500, body=json.dumps({"error": "server error"})
        ))
    
    page.goto("/orders")
    # 断言逻辑...
```

## 性能对比

| 方案 | 启动时间 | 单个请求延迟 | 维护成本 | 代码侵入性 |
|------|---------|------------|---------|-----------|
| Playwright Route | ~5ms | 0-10ms | 低 | 无 |
| WireMock Server | ~3s | 50-200ms | 高 | 需要配置 |
| Charles Proxy | ~30s | 100-500ms | 中 | 需要证书 |
| Nginx反向代理 | ~1s | 10-50ms | 高 | 需要配置文件 |

Playwright Route 方案在测试场景下综合优势明显——零配置、毫秒级切换、无进程依赖。

## 进阶方向

1. **HAR 录制与回放** — `page.route_from_har()` 可以直接录制真实 API 响应并在后续测试中回放，适合做回归测试套件
2. **WebSocket 拦截** — `page.route_websocket()` 可以拦截和修改 WebSocket 消息，适合测试实时应用
3. **结合 Faker 生成动态 mock 数据** — 每次测试用随机但符合规则的数据，发现更多边界情况
4. **覆盖率追踪** — 配合 code coverage 工具，统计 mock 覆盖的 API 接口比例，找出未被测试覆盖的端点

Playwright 的 Route API 看着简单，用好却需要理解浏览器的网络请求生命周期。掌握这些模式之后，90% 的前端测试依赖问题都可以在测试代码内部解决，不需要搭外部 mock 服务。
